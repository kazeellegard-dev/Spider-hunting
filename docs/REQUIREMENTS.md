# クモの巣ハンティング 要件定義書（v1.0 ドラフト）

最終更新: 2026-10-14
ステータス: 開発方式をWebアプリ＋Capacitorに転換（v1.1）。図鑑38種・強化6種・HUDアイコン追加（v1.2）。おなか/いとの分離・突風・ひかる糸（v1.3）。1日のめぐりと日数記録（v1.4）。ノーマルモード（現チャレンジモード）・広告枠・アプリ版の土台（v1.5）。ゲージを「いと」1本に戻し、タイトルを回転式のモード選択に。モードの台をタップしてメニューを開く2段構え、チャレンジモードはステージごとにランダムなきせかえ（v1.6）。糸がクロスすると自動でむすばれる（v1.7）。かぜで虫がにげやすくなる・にげた虫は糸を切ってフェードアウト（v1.8）。やり込み要素（おまもり・天気・むずかしさ★・図鑑ランクと大きさ記録・いろちがい・そろえ・きせかえのパーツ化・巣の見た目・背景の季節・称号・実績・今日のおだいとしずく交換）と、チャレンジモードのミッションを1行表示に（v1.9）。ブラウザで遊べる一通り完成版を `web/` に実装済み。遊んだ感触をもとに詳細を詰めるフェーズ。

## 0. 確定事項（v0.2で決定）

| 項目 | 決定内容 |
|---|---|
| 収益モデル | **広告＋課金ハイブリッド**。基本無料プレイ＋リワード広告（スタミナ回復・巣修復即時化・ボーナスステージ再挑戦等）＋アイテム課金（強化素材・広告除去等）を併用する。 |
| 表現の過激度 | **ライト表現**。虫は糸にぐるぐる巻きにされて少し間を置いてから「ポン」と消える演出とし、血・体液・断末魔等のグロテスク表現は一切含めない。対象年齢は12+相当を想定。 |
| 開発エンジン | **HTML5 Canvas（素のJavaScript）＋Capacitor**（v1.1で変更。旧: SpriteKit）。Webアプリとして開発し、確認端末のブラウザで都度動作確認する。最終的にCapacitorでiPhone/iPadアプリ化する（別リポジトリ「ねこだるまおとし」と同じ進め方）。広告・課金・Game Centerはアプリ版でのみプラグイン経由で有効化する。 |
| ゲームループ構造 | **ハイブリッド（エンドレス＋マイルストーン進行）**。1プレイはスタミナが尽きる／巣が破壊されるまで続くエンドレスの捕獲プレイ。並行して、累計スコアやレベルの節目（マイルストーン）でエリア（背景・出現する虫のセット）が切り替わり、ステージ制のような「進んでいる感」を演出する。個別のステージクリア／失敗判定は設けない。 |
| ガチャ要素 | **なし**。強化素材・コスチューム等はすべて価格固定の直接購入（またはゲーム内通貨での交換）とし、確率抽選による課金要素は導入しない。景品表示法上の確率表示義務や射幸性への配慮が不要になり、審査・法務面のリスクとUX上の不透明感を避けられる。 |
| iPad対応 | **対応**（v1.1で変更。旧: 一旦未対応）。Web版は画面サイズに合わせて遊ぶ範囲を広げる作りにしたため、iPadの縦横どちらでも遊べる。 |
| 多言語対応 | **日本語・英語の2言語**。日本国内向けは日本語表示、それ以外の地域はすべて英語表示とする（地域ごとの追加言語は行わない）。 |
| オンライン要素 | **Game Center対応（ランキングのみ）**。スコアランキングをGame Centerのリーダーボード機能で実装する。フレンド機能等の独自オンライン機能は設けない。 |

以降の各章は、この8点を前提として記述する。

### 0.0 Web版で仮決めした仕様（v1.1、2026-10-13）

ブラウザで一通り遊べる版を先に作り切るため、未決定だった部分を下記のとおり仮決めした。遊んだ感触をもとに見直す前提で、数値はすべて `web/js/data.js` に集約してある。

| 項目 | 仮決めした内容 |
|---|---|
| 1プレイの終わり方（F-05/F-15） | ゲージは「いと」1本（v1.3で「おなか」と2本に分けたが、おなかが減らず・いとが回復しにくく楽しさが落ちたためv1.6で戻した）。いとは糸を張ると長さに応じて減り、時間でも減る。時間での減り方はだんだん速くなる（強化しても必ず終わる）。0でおしまい。虫を食べると回復する（量は虫ごと、くいしんぼうで増える）。1回だけ「つづける」で半分回復できる（アプリ版ではその前にインタースティシャル広告を1回出す。読み込めていなければ広告なしでつづける） |
| 巣作り（F-12/F-13/F-17） | タップした場所へクモが糸を引きながら移動。近くの結び目や既存の糸に吸着してつながる。開始時は小さな巣が最初から張ってある |
| 捕獲（F-02/F-03） | 虫が糸に触れると「かかる」。かかった虫をタップするとクモが駆け寄って巻きつけ、ポンと消えて得点。放っておくと一定時間で逃げて糸を切る。虫の重さが糸の強さを超えると糸が切れて通り抜ける |
| コンボ | 3秒以内に続けて食べるとコンボ。得点倍率は最大3倍 |
| ゲームモード（v1.5／v1.6で名前と入口を変更） | **ノーマルモード**（ふつうの遊び方。上記の1日のめぐりで何日生きのびるか。コインで買う強化はこのモード用）と**チャレンジモード**（旧ノーマル）の2つ。別のゲームとして分けるため、タイトルは横並びのボタンをやめ、アーケードで台を選ぶように1モードずつ見せる。左右スワイプか ◀ ▶ で台がくるっと回る。台はモード名と短い説明だけにして、うしろで動くクモ（デモ）が見えるようにする。台をタップするとそのモードのメニューが開く（ノーマル: あそぶ・きょうか・きせかえ・ずかん・ランキング・あそびかた／チャレンジ: ステージ・ミッション・このステージのきせかえ・いまの強化・スタート・あそびかた）。きせかえ・ずかんはノーマルモードの機能で、チャレンジモードではステージごとにランダムなきせかえを一時的に借りる（同じステージのやり直しでは同じもの）。チャレンジモードで捕まえた虫は図鑑に記録しない。あそびかたはモードごとに別の内容。せっていは共通で、タイトル右上の歯車から開く。チャレンジモードは30ステージのミッション制（今後のアップデートで追加予定）。強化0から始まり、ステージをクリアするたびに強化を1つ選んで+1する（ノーマル専用の強化で、コインで買う強化・レベルの補正は使わない）。各ステージは時間帯・制限時間・1〜2個のミッション（虫の数、特定の虫、スコア、コンボ、おかし、ボス虫、重い虫、いきのびる）を持ち、全部達成でクリア。いとが0か時間切れで失敗し、同じステージをやり直す。進み具合と強化はセーブされ、「さいしょからやりなおす」でリセットできる。ステージの中身は `web/js/stages.js` |
| 広告（F-27） | 画面下にAdMobのアダプティブバナー。いとがなくなったあとの「広告を見て つづける」でインタースティシャル（いずれもいまはテスト広告。本番IDは README に記載）。EEA・英国ではUMPで同意を確認し、そのあと全員にATT（トラッキングの許可）を聞いてから表示（ATTがないと審査で却下される。ねこだるまおとし1.0で実例あり）。ゲーム画面はバナーの高さぶん上に収める。Web版は同じ位置を空けておく |
| ボーナスステージ（F-18〜F-21） | 食べた数でボーナスゲージがたまり、満タンで9秒間の「ボーナスタイム」。必要数は回を重ねるごとに増える。おかしが飛んできて、巣に触れると自動で取れる。虫は来ず、いとの時間での減りは半分になる。ボーナス中に1回「ひかりの糸巻き」が飛んできて、タップするとボーナス後15秒間「ひかる糸」になり、どんな虫でも捕まえられる（オニヤンマ・スズメバチ・ヘラクレスオオカブトはこの間しか捕まえられない） |
| エリア（F-05a） | v1.4で「1日のめぐり」に変更。あさ（30秒）→ひる（30秒）→ゆうがた（20秒）→よる（30秒）と進み、夜があけると「2にちめ」。時間帯ごとに背景・BGM・出る虫が変わる（あさ: チョウ・テントウムシ／ひる: セミ・トンボ・ハチ／ゆうがた: アキアカネ・カ・ガ／よる: ホタル・カブトムシ・クワガタ）。偶数日の夜は「ほしぞらのよる」でレアなカブト・クワガタが出る。重い虫は1日目は少なく、3日目から本来の数。日が進むほど虫が速く・多くなる。何日目まで生きのびたかを記録（タイトル・結果・ランキングに表示）。ひるいこうは40〜60秒ごとに「かぜ」（v1.8）。かぜで巣は切れないが、巣にかかっている虫のにげるメーターが1回で約3分の1進む。「とっぷう」は3日目から1日1回だけ来て、巣の約3分の1が切れたり飛ばされたりする（v1.5の仕様。v1.7で小さく多めにしたがv1.8で戻した）。にげた虫はかかっていた糸を切り、その場からフェードアウトして消える（もう一度はかからない） |
| 糸のむすび目（v1.7） | 新しく張った糸がほかの糸とクロスすると、そこが自動でむすばれる（両方の糸が切れずにつながる結び目になる）。むすばれた糸はむすび目1つにつき強さ+0.3（3つまで）で、重い虫もつかまえやすくなる。端の近くや、むすび目どうしが近すぎるところはむすばない。数値は `tieBonus` / `tieMax` |
| 虫（F-06） | 38種類（v1.2で11種から拡充）。ハエ・カ・テントウムシ・チョウ・ガ・ハチ・トンボ・ホタル・セミ・コガネムシ・クワガタ・カブトムシの12系統に、色違い・近縁種を加えた。重さ0.5（コバエ）〜12.5（ヘラクレスオオカブト）。キラキラ光るレア虫（オオムラサキ、タマムシ、きんのコガネ、オオクワガタ、コーカサス、ヘラクレス）はコインをくれる。ハチ類は逃がすと刺されていとが減る。初めて捕まえると「NEW!」表示 |
| 成長（F-07〜F-11） | スコアがそのまま経験値になりレベルアップ（糸の強さ・いとの量が少し伸びる）。コインはスコアの30分の1（v1.9.2で10分の1から変更）に、レア虫・おかし・実績などのコインが加わる。コインで6種の強化（糸のつよさ20段階／糸のりょう15段階／ねばねば・すばやさ・くいしんぼう・むしよせ各10段階）。強化画面に「いま→次」の値と、次に捕まえられる虫を表示する。ボス虫3種は強化しても捕まえられない（ひかる糸が必要） |

| やり込み要素（v1.9） | 夜明けのおまもり3択、日ごとの天気、むずかしさ★0〜10（7日目で次の★）、図鑑の銅銀金ランク、虫ごとの大きさ記録（最大・最小それぞれに金のライン）、いろちがい、系統ごとのそろえごほうび、実績82個（レベルの実績ではレベル限定のきせかえがもらえる）、今日のおだい（ごほうびはコインとは別の「しずく」。しずく交換でしか手に入らないきせかえあり）。ガチャなし・連続ログインの罰なし。詳細と数値は `docs/ENDGAME_IDEAS.md` 8章と `web/js/meta.js` |

### 0.1 開発エンジン選定理由（v1.0時点の記録。v1.1でWeb＋Capacitorに変更）

| 比較軸 | SpriteKit（採用） | Unity | Godot |
|---|---|---|---|
| 対応スキル | Swift経験ありなので学習コストほぼゼロ | C#/Unity未経験なら学習コスト大 | GDScript/C#とも未経験なら学習コスト大 |
| クロスプラットフォーム | iOS専用（今回はAndroid展開なしのため問題なし） | 強み（今回は活かせない） | 強み（今回は活かせない） |
| StoreKit/GameKit/広告SDK連携 | ネイティブAPIなので直結、余計なブリッジ層が不要 | プラグイン経由（Unity IAP、Mediation SDK等）でひと手間 | プラグインの成熟度が低くiOS IAP/広告まわりの事例が少ない |
| ビルド・審査 | Xcode標準ビルドのみで完結、アプリサイズも小さい | IL2CPPビルドでサイズ増・ビルド時間増の傾向 | 情報少なく審査事例の知見が薄い |
| ライセンス/コスト | 無料（Appleネイティブ） | 収益しきい値超過でUnityライセンス費が発生し得る | 無料（オープンソース） |
| 2D物理・糸表現 | 標準の`SKPhysicsJoint`では糸の柔軟な垂れ下がりは非対応。Verlet Integration等を自前実装する前提（T-02で詳細調査） | 高機能な物理エンジン・アセットが豊富だが今回はオーバースペック | 2D物理は一定水準だが糸表現の実装事例はSpriteKit同様に自前実装が必要 |

**結論**: 「iOS専用」「Swift経験あり」という2条件がUnity/Godotの強み（クロスプラットフォーム、豊富なアセットエコシステム）を打ち消すため、開発速度・保守性・審査の通しやすさで勝るSpriteKitを採用する。糸の物理表現はSpriteKit標準機能でカバーしきれないため、Verlet Integrationベースの自前実装を行う（T-02）。

### 0.2 ゲームループ構造の選定理由

| 比較軸 | ステージ制 | エンドレス制 | ハイブリッド（採用） |
|---|---|---|---|
| 既決の収益モデルとの相性 | スタミナ制と役割が重複し設計が複雑化しやすい（ライフ制との二重管理になりがち） | リワード広告での「スタミナ即時回復」がそのままコアループの継続動機になり、相性が良い | エンドレス部分はスタミナ制と直結。マイルストーンは広告・課金の追加動機（先出しでエリア解放等）にも使える |
| 進行感・目標の明確さ | 明確（クリア/未クリアが分かりやすい） | 弱い（スコアのみだと目標が単調） | エリア切り替え・新しい虫の解放で「進んでいる感」を補える |
| 実装コスト | ステージデータ・クリア条件・進行管理が必要で工数大 | 最小（スコアと難易度カーブのみ） | エンドレス基盤＋マイルストーン判定の追加のみで、ステージ制ほどの工数増にはならない |
| セッション長への影響 | ステージ設計次第で1プレイが伸びやすく、隙間時間向けのコンセプトとズレる | 1プレイ1〜3分の想定に合う | エンドレスと同様、1プレイの長さはスタミナで制御できる |

**結論**: 「広告でスタミナを回復して繰り返し遊ぶ」という既決の収益モデルに最も自然に接続できるのはエンドレス基盤であるため、これを採用する。ただし進行感を出すため、レベル・累計スコアの節目でエリア（背景・出現する虫のセット）が切り替わる「マイルストーン進行」を組み合わせる。個別のステージごとのクリア／失敗判定は設けない。

## 1. アプリ概要

| 項目 | 内容 |
|---|---|
| タイトル | 日本語「クモの巣ハンティング」／英語「Spider Web Catch」（App Store の名前は「Spider Web Catch: Bug Hunt」）。ホーム画面の名前は日本語「クモハン」／英語「Web Catch」 |

### 1.1 一言コンセプト
「巣を張り、待ち、仕留める」というクモらしい駆け引きを、タップ操作で気持ちよく再現するカジュアルゲーム。

## 2. ターゲットユーザー・想定ペルソナ

- カジュアルゲームを隙間時間に遊ぶ層（通勤・通学、待ち時間）
- 育成・コレクション要素が好きな層
- 虫や生き物モチーフに抵抗がない年齢層（要検討: 低年齢層向けにデフォルメ度を上げるか、ホラー/グロ表現を避けるか）

### 2.1 対象年齢・レーティング
- 表現方針は「ライト表現」（0章参照）に確定。虫が糸に巻かれてポンと消える程度で、血・グロ表現なし。App Store年齢レーティングは12+程度を想定（最終区分はB-01/B-02の調査結果で確定する）。

## 3. 機能要件

### 3.1 コアゲームプレイ：虫を捕まえる
- **F-01**: 画面内にハエ・蚊・蝶などの虫がランダムな軌道・速度で出現し、画面を横切って飛ぶ。
- **F-02**: クモの巣（糸）に虫が接触すると捕獲判定が発生する。
- **F-03**: 虫ごとに「重さ／耐糸力」パラメータを持ち、クモの糸の強度が虫の重さを下回ると糸が切れる（捕獲失敗、巣の一部破損）。
- **F-03a**: 捕獲成功時の演出は「ライト表現」に統一する。虫は糸にぐるぐる巻きにされ、短い間（1秒程度）を置いてから光の粒になってポンと消える。血・体液・断末魔などグロテスクな表現は一切含めない。
- **F-04**: 捕獲成功時にスコア・経験値・ゲーム内通貨を獲得する。
- **F-05**: ゲームループは「ハイブリッド（エンドレス＋マイルストーン進行）」に確定（0.2章）。1プレイはスタミナ（糸の総量、F-15）が尽きる、または巣が完全に破壊されると終了する。個別ステージのクリア／失敗判定は設けない。
- **F-05a**: 累計スコアまたはプレイヤーレベルが一定の節目（マイルストーン）に達すると、エリア（背景・出現する虫のセット）が切り替わる。エリア一覧・切り替え条件はゲームバランス設計（6章）で定義する。
- **F-06**: 虫の種類ごとに得点・出現頻度・出現エリア（F-05aのマイルストーンで解放）が異なる。

### 3.2 レベル・成長システム
- **F-07**: プレイヤー（クモ）にレベルの概念があり、経験値蓄積でレベルアップする。
- **F-08**: レベルアップにより「糸の強度」「巣の最大サイズ」「糸の伸ばせる本数」などのパラメータが向上する。
- **F-09**: 糸の強度が上がると、より重い（大きい）虫を捕獲できるようになり、出現する虫のバリエーションが解放される。
- **F-10**: レベル/強化要素をツリー状（スキル振り）にするか、単純な自動成長にするかは要検討。
- **F-11**: 成長は基本ゲーム内通貨（プレイで獲得）で進行できる設計とし、課金は「時短（強化素材の直接購入）」の位置づけとする。強化そのものを課金限定にはしない（無課金プレイヤーの離脱防止）。

### 3.3 巣の作成（タップでクモを移動・巣を張る）
- **F-12**: プレイヤーが画面上の任意の位置をタップすると、クモがその位置へ移動する。
- **F-13**: クモの移動軌跡、または指定した複数のアンカーポイント間に「糸」が自動的に張られ、巣の形状を構築する。
- **F-14**: 巣の形状（面積・網の密度・アンカー数）が捕獲率・耐久力に影響する設計とする。
- **F-15**: 糸の総量に上限があり（スタミナ／リソース制）、無限に巣を拡張できないようにする。
- **F-16**: 巣が虫や外的要因（風、天敵など）で破損した場合の修復手段（自動回復／タップで補修）を定義する。
- **F-17**: 巣作成のUI/UX：タップ位置の視覚的フィードバック（プレビュー線、糸を張れない範囲の表示など）。

### 3.4 ボーナスステージ
- **F-18**: 一定条件（コンボ数、特定アイテム取得、時間経過など）でボーナスステージへ移行する。
- **F-19**: ボーナスステージでは飴・お菓子などのアイテムが降ってくる／飛んでくる演出とし、通常ステージとは異なる収集目的とする。
- **F-20**: ボーナスステージで得たアイテムの用途（ゲーム内通貨、育成素材への直接交換など）を定義する。ガチャ的な抽選要素は使わない（0章で確定）。
- **F-21**: ボーナスステージの発生頻度・持続時間・難易度カーブを定義する。

### 3.5 その他機能（洗い出しレベル・優先度は要検討）
- **F-22**: タイトル／ホーム画面。ステージ選択画面は設けず、ホームから直接エンドレスプレイに入る導線とする。到達済みエリア・マイルストーン進捗はホーム画面上に表示する。
- **F-23**: 設定画面（サウンドON/OFF、通知設定、言語設定等）
- **F-24**: 実績・デイリーミッション・ログインボーナスなどのリテンション施策
- **F-25**: ランキングはGame Center連携（リーダーボード）で実装する（0章で確定）。フレンド機能等の独自オンライン機能は設けない。
- **F-26**: チュートリアル（初回起動時の操作説明）
- **F-27**: 収益化は「広告＋課金ハイブリッド」（0章で確定）。内訳案:
  - リワード広告: スタミナ（糸の総量）即時回復、巣の即時修復、ボーナスステージ再挑戦、獲得通貨2倍
  - バナー広告: ホーム画面下部など非プレイ画面中心に表示し、プレイ体験は阻害しない
  - アイテム課金: 強化素材パック、限定コスチューム（クモの見た目）、広告完全除去パス（いずれも価格固定の直接購入。ガチャ的な確率抽選要素は導入しない）
- **F-28**: プッシュ通知（巣の修復完了、スタミナ回復、イベント告知など）

## 4. 非機能要件

| 分類 | 要件（案） |
|---|---|
| 対応OS | iOS 16以上を想定（要最終決定） |
| 対応端末 | iPhone SE以降の主要機種とiPad |
| フレームレート | 60fps（軌道計算・物理演算のパフォーマンス確保） |
| オフライン対応 | 基本オフラインでプレイ可能、Game Centerランキング送信/課金/広告時のみ通信 |
| データ保存 | ローカル保存必須、iCloud経由の機種間引き継ぎは要検討 |
| ローカライズ | 日本語・英語の2言語（0章で確定）。日本国内は日本語、それ以外の地域は英語表示。地域別の追加言語（中国語・韓国語等）は今回対象外 |
| アクセシビリティ | 色覚多様性対応（虫の視認性）、VoiceOver対応の要否 |
| セキュリティ/プライバシー | 個人情報を扱わない前提だが、広告SDK・分析SDK導入時はATT（App Tracking Transparency）対応が必要 |
